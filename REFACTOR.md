# TandemMP Refactor Guide

## Goals

1. **Production-quality code and structure** — typed, tested, linted, with clean public APIs and
   a `src/` layout installable via `pyproject.toml`.
2. **Speed** — accelerate hot paths with Rust (PyO3) where profiling justifies it, and replace
   inefficient Python patterns (list-comprehension loops over particles/events) with vectorised
   NumPy or batched Rust calls.
3. **Test-driven refactoring** — for every module being refactored, write tests *first* against
   the desired production-quality API (not the current one). The tests pin the correct behaviour
   so the rewrite can be validated automatically.

## Project overview

TandemMP is a Python package for pair matching and particle tracking analysis of iSCAT microscopy data. 

### Current structure (pre-refactor)

```
tandemmp/             # main package (flat, no src/ layout)
  utils/              # utility grab-bag (conversions, fit, image, kalman, etc.)
  plotting/           # matplotlib helpers
  io/                 # load / save
  simulation/engine/  # Monte Carlo particle simulation
  rust/               # existing PyO3 crates (fit_psf, psf_a12ws, psf_traits)
alex_area/            # experimental/analysis scripts (not part of core package)
archive/              # deprecated code
setup.py              # legacy setuptools
```

### Target structure (post-refactor)

```
src/tandemmp/         # src-layout package
  core/               # enums, dataclasses, parameters, constants
  fitting/            # PSF fitting, Gaussian fitting, 3D ratiometric
  tracking/           # particle, manager, kalman, pair matching
  events/             # event classes (ratiometric, subtraction, ghost)
  drift/              # drift correction
  io/                 # load / save
  pipeline/           # loader, investigator, PCA, batch_process
  plotting/           # all plotting
  simulation/         # simulation engine
  _rust/              # PyO3 extension modules
tests/                # mirrors src/tandemmp structure
notebooks/            # analysis notebooks (moved from alex_area)
pyproject.toml        # replaces setup.py
```

## Refactoring order

Each step follows the same pattern:
1. Write tests for the target API of the module being refactored.
2. Refactor the module to pass those tests.
3. Move the refactored module into its target location under `src/tandemmp/` (see target
   structure above). Only refactored, tested code goes into `src/`.
4. Update downstream importers.
5. Verify CI is green (once enabled).

## Cross-cutting concerns

### Ghost prediction model

The ghost detection system spans multiple refactoring layers and must be migrated carefully to
preserve functionality. It has three components:

1. **ML classifier** (`ghost_signal_ML` in `events.py`) — a TensorFlow/Keras CNN loaded from
   `utils/GP_model.h5`. Used as a decision threshold (`> 0.5`) in `investigator.py` and
   `particle.py`. Training data in `resources/GPDatasets/` (True/False `.npy` files).
2. **Heuristic signal** (`ghost_signal()` in `events.py`) — logistic function on averaged
   residual images, no ML dependency.
3. **Correction & matching** — `correct_ghost()` in `utils/image.py` subtracts a PSF model;
   `match_ghost()` and `double_check_ghost()` in `investigator.py` use spatial overlap
   probabilities to match ghost particles.

**Migration notes:**
- `get_GPModel()` in `__init__.py` imports TensorFlow at package level — refactor to a lazy
  import so TF is only required when ghost ML scoring is actually used.
- Best implementation pattern for `get_GPModel()`: use a dedicated loader function with
  `@functools.lru_cache(maxsize=1)` (or equivalent singleton caching), import TensorFlow *inside*
  that function, resolve the packaged model path via `importlib.resources`, and load the model on
  first use only. This keeps package import fast while avoiding repeated TensorFlow/model loads
  once ghost scoring begins.
- `GP_model.h5` path is resolved via `tandemmp.__file__` — will break in src-layout. Use
  `importlib.resources` instead.
- The `0.5` threshold is hardcoded in multiple files — consolidate into a parameter.
- **Testing:** load the saved `.npy` training data, run through the model, and assert True
  examples score > 0.5 / False examples < 0.5. This pins model behaviour without live data.

## Conventions

- **Python >=3.10**, type-annotated public APIs (`mypy --strict` on `src/`).
- **ruff** for linting and formatting (line length 88).
- **pytest** for all tests; tests live in `tests/` mirroring the `src/` structure.
- **No `tkinter` dialogs in library code** — file paths are passed as arguments, not selected
  interactively. Interactive file selection belongs in CLI entry points or notebooks only.
- **No wildcard imports** (`from module import *`).
- **Dataclasses or NamedTuples** over ad-hoc dicts for structured data.
- **Snake_case** for all module filenames (no `PCA.py`, `DriftCorrector.py`).

## Branching strategy

- **`refactor`** is the integration branch for all refactor work — treat it as the "main" branch
  for the refactor effort. Finished, reviewed layer branches are merged back into `refactor`.
  `main` only receives code from `refactor` once a layer (or set of layers) is fully validated.
- **Layer branches** are created from `refactor` (or from the latest preceding layer branch) and
  group related refactor items. Naming convention: `layer<id>-<short-description>`, e.g.
  `layer1cde-refactor`, `layer1b-events-subpackage`.
- **Item branches** for individual files or tasks branch off the latest layer branch that
  contains their dependencies. For example, to refactor item 1f (`DriftCorrector.py`), create a
  branch from the tip of the current layer-1 branch (e.g. `layer1cde-refactor`). This ensures
  the work starts with all prerequisite refactored modules already in place.
- PRs for item branches target their parent layer branch, not `refactor` directly.
- Once all items in a layer branch are merged and CI is green, the layer branch is merged into
  `refactor`.

## CI strategy

CI workflows are **enabled** and scoped to refactored code only:

- **Triggers** — `push` to `main`/`refactor` and all PRs, filtered by `paths: src/**, tests/**,
  pyproject.toml`. Changes to old `tandemmp/` directory do not trigger CI.

## open_iscat dependency

`open_iscat` is a private GitHub repo and is **not listed in `pyproject.toml`**. It is not on
PyPI and its codebase has not been updated for Python >=3.10, so including it as a dependency
would break CI.

**Current workaround:** `pipeline/open_iscat.py` uses lazy imports — `open_iscat`, `h5py`, and
`nptdms` are imported inside function bodies (`load_mp_file`, `run_pipeline`,
`_read_mp_metadata`, `_read_tdms_metadata`), not at module level. The data containers (`Info`,
`Movie`, `PipelineResults`) and their tests work without any of these packages installed.

**Revisit after refactor is complete:**
- [ ] Refactor `open_iscat` to support Python >=3.10.
- [ ] Publish `open_iscat` to PyPI (or a private index) or use a git URL dependency.
- [ ] Add `open_iscat` to `pyproject.toml` dependencies (or an optional extra).
- [ ] Move `h5py` and `nptdms` from lazy imports to declared dependencies.
- [ ] Add integration tests for `load_mp_file` and `run_pipeline` that exercise the full
  `open_iscat` pipeline.
